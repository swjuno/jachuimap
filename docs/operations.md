# 공개 전 운영 점검

## 이번 구현의 범위

- 점수 배점은 그대로 유지합니다. 결과 전 자리표시 광고와 공개 Raw Debug UI를 제거했습니다.
- `/scoring`에서 배점·브랜드 필터·검색 제한·데이터 출처를 확인할 수 있습니다.
- `/api/score`: production에서 인스턴스당 IP 해시별 10회/분, 동시 요청 4개. 제한 시 429 + `Retry-After`와 재시도 UI를 제공합니다.
- Vercel에서만 `x-vercel-forwarded-for`를 신뢰합니다. 그 외 환경·유효하지 않은 헤더는 공통 제한 버킷을 사용합니다. 다른 호스팅으로 이전할 때 신뢰 프록시 구성을 함께 검토해야 합니다.
- 성공한 시설 정보만 10분 캐시, 최대 200건. 같은 좌표의 동시 조회는 하나로 합칩니다. 실패·부분 결과는 캐시하지 않습니다. 좌표를 반올림하지 않아 점수 경계가 바뀌지 않습니다.
- IP 원문은 저장하지 않고 프로세스별 임시 비밀값으로 HMAC 처리합니다. 요청 버킷 최대 1,000개, 1분 만료 후 다음 요청 시 정리합니다.
- 카카오 HTTP 요청은 각각 4초, 분석용 외부 조회 전체는 10초 내 중단합니다. 12개 조회 중 하나라도 실패하면 정상 점수를 반환하지 않습니다.
- 30일이 지난 공유는 점수 스냅샷만 만료됩니다. 서명된 위치를 확인해 현재 분석으로 연결합니다. 비밀키 교체·유실이나 위조된 토큰까지 복원하지는 않습니다.

## 한계: 공개 홍보 전에 별도 결정 필요

이 메모리 제한과 캐시는 **인스턴스별 보조 방어**입니다. 서버리스 콜드 스타트·여러 인스턴스·IP 변경을 통한 분산 요청에는 전역 한도를 보장하지 않습니다. 동일 IP를 공유하는 사용자는 제한을 공유합니다.

공개 홍보 전에는 관리형 방화벽 또는 원자적으로 집계하는 공유 저장소 기반 제한을 도입해야 합니다. 계정 연결·과금·데이터 처리 범위가 달라지므로 운영자 승인을 받은 뒤 진행합니다. 현재 구현만으로 카카오 전체 쿼터를 보호한다고 판단하지 마세요.

공유 토큰과 GET 분석 URL에는 좌표가 포함됩니다. 앱 로그에서 제외해도 호스팅 접속 로그·브라우저 기록·공유 서비스에는 URL이 남을 수 있습니다. 비밀키는 서버 환경변수로만 보관하세요.

## 로그와 대응

Vercel 프로젝트의 Runtime Logs에서 `score_request`를 검색합니다. 앱은 URL·IP·좌표·주소·토큰·API 키·원본 오류를 기록하지 않습니다.

```json
{"event":"score_request","status":503,"code":"INFRASTRUCTURE_FETCH_FAILED","durationMs":4010}
```

- `OK`: 정상 결과. `DEMO`: 실제 키가 없어 데모 응답. Production의 DEMO는 키 등록 여부를 점검합니다.
- `RATE_LIMITED`: 429. 네트워크를 공유하는 정상 사용자 집중인지 자동화 요청인지 확인합니다.
- `INFRASTRUCTURE_FETCH_FAILED` / `GEOCODING_FAILED`: 503. 카카오 앱 쿼터·REST 키 권한·외부 서비스 상태를 확인합니다. 원본 사용자 URL을 로그에 추가하지 마세요.
- 같은 시간 구간에서 `status >= 500` 건수 / 전체 `score_request` 건수로 실패율을 확인합니다. 제한율(429)은 따로 계산합니다.
- 자동 알림은 아직 연결하지 않았습니다. 알림 채널과 외부 로그 서비스 도입은 승인 후 연결합니다. 즉시 장애 감지 체계가 완성된 상태는 아닙니다.

## 실기기 검증표 (자동 테스트와 별도)

아래 항목은 iOS Safari·Android Chrome·카카오톡 인앱 브라우저에서 실제 배포 후 확인하고 기록합니다.

- [ ] 320/375/390px 수준 화면에서 지도 → CTA → 안내 → GPS, 첫 화면 CTA 노출
- [ ] 검색·GPS 권한 허용/거부·지도 드래그 후 요청 위치가 동일함
- [ ] 2.8초 스캔, 결과 직행, 중복 클릭 방지, 사용자 스크롤 시 후속 자동 이동 중단
- [ ] 400·503에서 점수가 보이지 않고 같은 위치 재시도 가능
- [ ] 429에서 대기 시간 표시 후 재시도 가능
- [ ] 시스템 공유 성공·취소·클립보드·PNG 저장, 공유받은 링크 자동 분석 1회
- [ ] 카카오톡 새 공유 카드의 점수, 만료된 카드의 안내, 기존 링크 복원
- [ ] GA4 Realtime에서 시작/완료/실패·공유 이벤트 수신. 정확한 점수·좌표·주소·URL이 이벤트에 없는지 확인

## 호스팅·검색 등록

[Vercel Hobby 공식 문서](https://vercel.com/docs/plans/hobby)는 개인·비상업적 이용을 대상으로 합니다. 광고·제휴 수익을 도입하기 전에 상업 이용 가능한 요금제 또는 호스팅을 승인받아 선택하세요. 이번 작업은 구독·결제·도메인 구매를 실행하지 않습니다.

기존 도메인 기준 `/sitemap.xml`, `/robots.txt`를 제공합니다. 공유 토큰 URL은 사이트맵에 넣지 않으며 공유 페이지의 `noindex`를 유지합니다. 독립 도메인 확정 시 layout의 metadataBase·OG URL과 sitemap·robots의 도메인을 함께 갱신합니다. Search Console·네이버 등록에는 운영자 소유권 확인이 필요합니다.

## 다음 제품 확장 제안

먼저 현재 점수에 사용된 필터 결과만 시설 마커로 공개하고, 역지오코딩은 동 단위 주소만 선택적으로 표시하는 방향을 권장합니다. 이후 최근 두 후보 비교를 도입할 수 있습니다. localStorage에 주거 후보 좌표를 영구 보관하는 것은 개인정보 처리 범위 변경이므로 저장 기간·삭제 UI·동의 방식을 결정한 뒤 진행합니다. 백화점 배점 변경은 별도 승인 없이 하지 않습니다.
